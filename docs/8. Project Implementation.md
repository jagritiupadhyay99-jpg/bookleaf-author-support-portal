# Project Implementation Plan

## Goal
Deliver the smallest complete, secure, demonstrable application in the three-day window.

## Milestone 0 — Workspace inspection
- Inspect current directory and uploaded JSON file.
- Confirm Node/npm versions.
- Do not overwrite any existing work.
- Create `.gitignore` before initializing Git.

## Milestone 1 — Scaffold
- Create `client/` React + Vite app.
- Create `server/` Express app.
- Add `/api/health`.
- Confirm client and server start independently.
- Add `.env.example` files.

**Exit criteria:** frontend loads; API health endpoint returns `ok`.

## Milestone 2 — Seed data
- Copy provided JSON into server seed/data location.
- Create user and book schemas.
- Seed 10 author users and 18 books.
- Hash demo passwords.
- Seed admin using environment variables.
- Make seeding idempotent.

**Exit criteria:** seed summary confirms 10 authors and 18 books; rerunning does not duplicate them.

## Milestone 3 — Authentication and authorization
- Login/logout/me endpoints.
- Password hash verification.
- JWT/session handling.
- `requireAuth`, `requireRole`, and ownership checks.
- Frontend route guards.

**Exit criteria:** author and admin can sign in; author cannot access another author's book/ticket.

## Milestone 4 — Author features
- Dashboard and book table.
- Null-safe formatting.
- Ticket form with book dropdown plus General / Account Level.
- My Tickets and ticket detail.
- Public message timeline.

**Exit criteria:** an author can submit a ticket and see it listed.

## Milestone 5 — Admin features
- Queue and filters.
- Priority/category display and overrides.
- Ticket details.
- Assign-to-me.
- Status update.
- Internal notes.
- Public response composer.

**Exit criteria:** admin can complete a ticket workflow and author can see the reply.

## Milestone 6 — AI
- LLM provider service.
- Category + priority analysis on new ticket.
- AI draft generation on explicit admin action.
- JSON validation and timeout.
- Fallback when key missing or provider fails.
- Admin can override all AI suggestions.

**Exit criteria:** live AI works with configured key; no-key mode remains usable and visibly identified.

## Milestone 7 — Polling and UX
- Poll ticket data every 5–10 seconds where needed.
- Cancel timers on unmount.
- Add loading, error, empty, and success states.
- Test mobile/table layout.

## Milestone 8 — Quality and delivery
- Run build and smoke tests.
- Test all edge cases.
- Deploy backend, then frontend.
- Seed demo environment.
- Write README and one-page approach note.
- Verify demo credentials and URLs.
- Create private repo and invite evaluator when email is supplied.

## Suggested three-day schedule
### Day 1
Scaffold, seed data, authentication, author dashboard, ticket creation/listing.

### Day 2
Admin queue and workflow, AI classification/priority/draft, polling, error fallback.

### Day 3
Security and edge-case testing, deploy, README, approach note, final smoke test.

## Definition of done
A feature is not done merely because the page exists. It must work through the UI, API, and persistence layer, and have sensible errors and permissions.
