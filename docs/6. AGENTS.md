3. Keep the repository private. Do not publish this assignment or its solution to a public repository.

8. Internal notes must never appear in author API responses.
9. Handle null dates/MRP/royalty metadata and zero values without crashes.
10. Prefer simple, understandable code that the candidate can explain in a technical interview.

## AI implementation requirements
- Use a provider abstraction such as `generateTicketAnalysis()` and `generateResponseDraft()`.
- Put provider calls only on the server.
- Pass only the ticket description, subject, relevant book fields, and compact policy context.
- Ask for structured JSON; parse and validate it against allowed category/priority values.
- On invalid JSON, timeout, missing key, rate limit, or provider failure, preserve the ticket and allow manual admin action.
- Use the provided knowledge base in `PRD.md` / assignment. Do not invent policies.
- Make the prompt insist that unknown facts are not to be invented.
- Add a timeout and bounded output size.
- AI output is always a suggestion, not a decision that cannot be overridden.
