# Database Design

## Principles
- Use the provided JSON as the authoritative seed dataset.
- Preserve the source author IDs and book IDs when possible.
- Normalize authors and books into separate collections/tables, rather than duplicating the full author record inside every ticket.
- Every ticket must have an author/user owner.
- Internal notes and public replies must be distinguishable.
- Use timestamps for ticket creation/update and message creation.
- Handle null source fields safely.

## Collections / tables

### users
| Field | Type | Notes |
|---|---|---|
| _id | ObjectId/UUID | Primary identifier |
| authorId | string, nullable | Source ID such as AUTH001; null for admin |
| name | string | Display name |
| email | string | Unique, normalized lowercase |
| phone | string, nullable | Seeded source field |
| city | string, nullable | Seeded source field |
| joinedDate | date, nullable | Source field |
| passwordHash | string | Never store plaintext |
| role | enum | `author` or `admin` |
| createdAt / updatedAt | date | Timestamps |

### books
| Field | Type | Notes |
|---|---|---|
| _id | ObjectId/UUID | Database identifier |
| bookId | string | Source ID BK001–BK018; unique |
| authorId | reference | References users.authorId or user document |
| title | string | Required |
| isbn | string, nullable | Preserve supplied value |
| genre | string, nullable | Source field |
| publicationDate | date, nullable | Null for in-production records |
| status | string | Preserve source status |
| mrp | number, nullable | Null allowed |
| authorRoyaltyPerCopy | number, nullable | Null allowed |
| totalCopiesSold | number | Default 0 |
| totalRoyaltyEarned | number | Default 0 |
| royaltyPaid | number | Default 0 |
| royaltyPending | number | Default 0 |
| lastRoyaltyPayoutDate | date, nullable | Null allowed |
| printPartner | string, nullable | Null allowed |
| availableOn | string[] | Empty array allowed |
| createdAt / updatedAt | date | Timestamps |

### tickets
| Field | Type | Notes |
|---|---|---|
| _id | ObjectId/UUID | Ticket ID |
| ticketNumber | string | Human-friendly ID, unique |
| authorUserId | reference | Ticket owner |
| bookId | string, nullable | `null` means general/account level |
| subject | string | Required |
| description | string | Required |
| category | enum | One of six assignment categories |
| categorySource | enum | `ai`, `admin`, `default` |
| priority | enum | Critical, High, Medium, Low |
| prioritySource | enum | `ai`, `admin`, `default` |
| status | enum | Open, In Progress, Resolved, Closed |
| assigneeUserId | reference, nullable | Admin owner |
| aiAnalysisStatus | enum | `pending`, `complete`, `unavailable`, `failed` |
| aiDraft | string, nullable | Draft only; not a sent message |
| internalNotes | array | Private admin-only notes |
| messages | array | Public conversation messages |
| createdAt / updatedAt | date | Timestamps |
| lastActivityAt | date | Used for queue sorting |

### messages (embedded in tickets for MVP)
- `messageId`
- `senderUserId`
- `senderRole` (`author` or `admin`)
- `body`
- `visibility` (`public`)
- `createdAt`

### internalNotes (embedded in tickets for MVP)
- `noteId`
- `adminUserId`
- `body`
- `createdAt`
- Internal notes must never be included in author-facing API responses.

## Indexes
- users: unique index on normalized email.
- books: unique index on bookId; index on authorId.
- tickets: index on authorUserId + createdAt; index on status + priority + createdAt; index on category; index on assigneeUserId.
- Ensure the API checks ownership, not merely that an ID exists.

## Seed strategy
- Read `bookleaf_sample_data(1).json`.
- Create author users from each `authors[]` record.
- Create a separate book record for every nested `books[]` entry.
- Seed deterministic demo passwords by hashing a configured password (e.g. `DEMO_AUTHOR_PASSWORD`) for all seeded authors; never store it in source code as a production secret.
- Seed one admin from environment variables (`ADMIN_EMAIL`, `ADMIN_PASSWORD`) and hash the password.
- Make seed command idempotent: upsert by source IDs instead of duplicating records.
- Do not run destructive collection drops in production.

## Data integrity and edge cases
- Keep numeric zero as zero.
- Keep null MRP/publication dates/payout dates as null in storage.
- UI formats null as “Not available”.
- Do not derive or recalculate historical royalty values from copies sold; display supplied totals.
- General/account-level tickets may have no bookId.
- Validate that an author can only attach a ticket to a book they own.
