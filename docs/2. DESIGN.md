# UX and UI Design Specification

## Design principles
- Clean, trustworthy publishing-operations product; functional over decorative.
- Clear role separation: Author Portal and Admin Portal.
- Responsive layouts for laptop and mobile widths.
- Use readable typography, generous spacing, clear labels, and consistent status badges.
- Make missing data understandable; never display raw `null` or broken UI.
- Use accessible form labels, visible keyboard focus, semantic buttons, and sufficient contrast.

## Visual direction
Use a restrained editorial SaaS style:
- Background: light neutral gray/off-white.
- Surfaces: white cards with subtle borders.
- Primary color: deep blue/teal.
- Accent: warm amber for pending/high-attention states.
- Typography: system font stack or a single locally available sans-serif.
- Rounded corners should be modest, not excessively pill-shaped.
- Avoid unnecessary animations and complex charts.

## Shared shell
- Top bar with BookLeaf wordmark/text, current portal label, signed-in user, and logout.
- Optional left sidebar on desktop; collapsible navigation on small screens.
- Toast/banner messages for success and errors.
- Loading skeleton/spinner and meaningful empty states.

## Author portal screens
### 1. Login
- Email and password fields.
- Validation messages.
- Demo credentials visible in README, not hardcoded as a secret in the UI.
- Error for invalid credentials without revealing whether an email exists.

### 2. Dashboard
- Summary cards: total books, published/live books, total copies sold, pending royalties.
- Book table/cards with title, status, ISBN, genre, copies sold, royalty earned/paid/pending.
- MRP/publication date may be absent for production books; show “Not available”.
- Do not assume all books are published.

### 3. Submit a ticket
Fields:
- Book dropdown including “General / Account Level”.
- Subject (required, sensible max length).
- Detailed description (required, sensible max length).
- Optional attachment picker with text stating upload is not enabled in the MVP.
- Submit and cancel actions.
After submit, show confirmation and link to the ticket.

### 4. My Tickets
- List of own tickets, sorted newest first by default.
- Subject, ticket ID, category, priority, status, created date, latest response preview.
- Ticket detail with original query, public responses in chronological order, and current status.
- Poll for updates every 5–10 seconds while page is open; stop polling on unmount.

## Admin portal screens
### 1. Overview / queue
- KPI cards: open tickets, critical/high priority tickets, unassigned tickets, resolved tickets.
- Ticket table: subject, author, category, priority, status, created date, assignee.
- Filters: status, category, priority, date range; search by subject/author/ticket ID.
- Default sort: unresolved tickets first, then highest priority, then oldest first.
- Clearly distinguish AI-suggested fields from admin-overridden fields.

### 2. Ticket detail
- Header with ticket ID, subject, author, linked book, status and priority.
- Original author description.
- AI category and priority, with editable overrides.
- Assignee selector / “Assign to me”.
- AI response draft editor with Generate Draft and Send Response actions.
- Internal notes section visually distinct from public replies.
- Status update control.
- Public conversation timeline.

## Status and priority presentation
- Use both text and color; never communicate state by color alone.
- Status: Open, In Progress, Resolved, Closed.
- Priority: Critical, High, Medium, Low.
- Add a subtle “AI suggested” label and “Manually changed” indicator where applicable.

## Empty/error/loading states
- No tickets: explain how to create a first ticket.
- No books: show helpful message and preserve dashboard layout.
- AI unavailable: show manual review/draft controls rather than a blocking error.
- API unavailable: show retry action and friendly message.
- Form validation: inline and specific.
- Avoid exposing stack traces or server internals to users.

## Minimum screen widths and responsive behavior
- Desktop: full sidebar and wide tables.
- Tablet/mobile: sidebar becomes menu; tables can scroll horizontally or convert to stacked cards.
- Keep primary action buttons visible and usable on touch screens.
