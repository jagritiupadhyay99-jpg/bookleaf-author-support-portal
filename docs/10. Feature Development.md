# Feature Development Guide

## 1. Authentication
- Normalize email to lowercase and trim whitespace.
- Verify password with bcrypt.
- Return minimal user profile only.
- Protect routes on server and client.
- Use role checks for admin APIs.
- Verify ownership on every author-specific resource endpoint.

## 2. Book dashboard
- Query books by authenticated user's author ID.
- Display provided totals directly; do not recalculate royalty totals.
- Format rupee values with `Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' })`.
- Format dates defensively.
- Null means “Not available”; numeric zero should show ₹0 or 0, not “Not available”.
- Production books should still appear in the book list.

## 3. Ticket creation
- Validate book belongs to author, unless General / Account Level selected.
- Save ticket before optional AI analysis can delay or fail.
- Initial status: Open.
- Initial default priority/category can be set to Medium/General Inquiry until AI succeeds.
- Store source metadata (`ai`, `admin`, `default`) so overrides are clear.
- Provide ticket number and confirmation to author.

## 4. Classification
Allowed categories:
1. Royalty & Payments
2. ISBN & Metadata Issues
3. Printing & Quality
4. Distribution & Availability
5. Book Status & Production Updates
6. General Inquiry

Ask the model to return JSON only, validate values, and fall back to `General Inquiry` if invalid. Do not trust arbitrary model-generated labels.

## 5. Priority
Allowed values: Critical, High, Medium, Low.
Guidelines:
- Critical: immediate risk or severe urgent issue, if supported by the query.
- High: ISBN mismatch, substantial overdue royalty concern, serious printing defects, or time-sensitive production/distribution issue.
- Medium: ordinary account/book questions requiring investigation.
- Low: informational or non-urgent metadata questions.
These are operational heuristics; keep the final priority editable by admin.

## 6. Response drafting
The model should:
- Acknowledge the author's concern.
- Use BookLeaf's supplied policies accurately.
- Avoid making up facts or actions.
- Give a next step and a clear timeframe only where supported by policy or a reasonable investigation commitment.
- Be professional and empathetic.
- Never send the draft automatically.

## 7. Admin management
- Filters should combine rather than overwrite each other.
- Search subject, author name, and ticket number.
- Queue sort should put unresolved tickets before resolved/closed, then higher priority and older unresolved tickets first.
- Assign-to-me sets current admin ID.
- Internal notes are private.
- Sending a response creates a public message and updates `lastActivityAt`.

## 8. Polling
- Poll only pages that need live updates.
- Use 5–10 second interval.
- Stop interval when component unmounts.
- Prevent overlapping requests where practical.
- Show last-updated time or subtle update state if time permits.

## 9. File attachment
Attachment is optional and UI-only is acceptable. If implemented as UI-only:
- Allow selecting a file but do not claim it was uploaded.
- Show a note that file upload is not enabled in this demo.
- Do not send large file contents to the API.

## 10. Keep the scope controlled
Do not implement WebSockets, email delivery, complex analytics, or file storage until the core ticket flow and AI fallback are working.
