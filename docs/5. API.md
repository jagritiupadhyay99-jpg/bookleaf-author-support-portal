# REST API Contract

Base path: `/api`  
Content type: `application/json` unless otherwise noted.

## Authentication
### `POST /api/auth/login`
Request:
```json
{ "email": "priya.sharma@email.com", "password": "<demo-password>" }
```
Response: authenticated user summary and session/token. Do not return password hashes.

### `POST /api/auth/logout`
Invalidate/clear the session cookie or clear client token according to chosen auth strategy.

### `GET /api/auth/me`
Return current authenticated user: id, name, email, role, and authorId if applicable.

## Author endpoints
### `GET /api/author/books`
Returns only the authenticated author's books.

### `GET /api/author/dashboard`
Returns safe summary values and the author's own books. Summary should use supplied figures and handle nulls.

### `POST /api/tickets`
Request:
```json
{
  "bookId": "BK001",
  "subject": "Question about my royalty payment",
  "description": "I would like to understand my pending royalty balance."
}
```
Use `bookId: null` for General / Account Level. The server determines authorUserId from authentication; never trust an owner ID supplied by the client.
Response: created ticket and AI analysis status.

### `GET /api/tickets/my`
Returns only the current author's tickets and public messages. Never include internal notes.

### `GET /api/tickets/:ticketId`
Author access only if ticket belongs to current user. Return public messages, not internal notes.

## Admin endpoints
All require authenticated `admin` role.

### `GET /api/admin/tickets`
Query parameters:
- `status`
- `category`
- `priority`
- `from`
- `to`
- `search`
- `sort` (e.g. `priority_oldest`)
- `page`, `limit`

Returns filtered tickets with author/book summary.

### `GET /api/admin/tickets/:ticketId`
Returns ticket detail, public messages, AI metadata, and internal notes.

### `PATCH /api/admin/tickets/:ticketId`
Allowed fields: `status`, `category`, `priority`, `assigneeUserId`. Validate each field and record category/priority source as `admin` when overridden.

### `POST /api/admin/tickets/:ticketId/assign-to-me`
Assigns current admin as assignee.

### `POST /api/admin/tickets/:ticketId/notes`
Request: `{ "body": "Internal follow-up note" }`. Never expose this response to authors.

### `POST /api/admin/tickets/:ticketId/ai-draft`
Generates and returns a draft based on ticket content, relevant book data, and knowledge base. Does not send the draft to the author.

### `POST /api/admin/tickets/:ticketId/messages`
Request: `{ "body": "Reviewed response text", "statusAfterSend": "In Progress" }`
Creates a public admin response. Optionally updates status. Do not send an empty response.

### `POST /api/admin/tickets/:ticketId/reanalyze`
Optional: reruns AI classification and priority analysis on explicit admin action.

## Health endpoint
### `GET /api/health`
Returns `{ "status": "ok" }` without exposing secrets or infrastructure details.

## Response conventions
Success:
```json
{ "data": {}, "message": "Optional human-readable message" }
```
Error:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Please provide a subject and description."
  }
}
```

## Status codes
- `200`: successful read/update
- `201`: created
- `400`: validation error
- `401`: missing/invalid authentication
- `403`: role/ownership forbidden
- `404`: record not found
- `409`: duplicate/conflict
- `429`: rate limited
- `500`: unexpected server error

## Validation and security
- Trim strings and reject empty subject/description.
- Apply reasonable maximum lengths.
- Validate enum values and dates.
- Use server-side ownership checks.
- Never accept authorUserId from author request body.
- Never expose internal notes through author endpoints.
- Never expose LLM API keys or password hashes.
- Add pagination to admin ticket list if time allows.
