# Debugging Playbook

## First response to any bug
1. Reproduce the problem.
2. Check browser console and Network tab.
3. Check server terminal logs.
4. Identify whether the problem is frontend, API, database, authentication, or AI provider.
5. Fix the root cause, then retest the original flow.
6. Do not paste secrets, tokens, or full environment files into logs or chat.

## Common issues

### `node` or `npm` command not found
- Install Node.js LTS.
- Restart VS Code/terminal.
- Verify `node -v` and `npm -v`.

### Port already in use
- Stop the previous dev server or choose a different `PORT`.
- Ensure frontend API URL points to the actual backend port.

### CORS error
- Set `CLIENT_ORIGIN` to the exact frontend origin.
- Ensure credentials/cookie options match the chosen auth design.
- Do not use unrestricted CORS in production.

### MongoDB connection error
- Verify `MONGODB_URI`.
- Check database credentials and URL encoding.
- Confirm Atlas network access rules and service status.
- Avoid logging the full connection URI.

### Seed data duplicated
- Use upsert keyed by `authorId` and `bookId`.
- Do not create new rows blindly on every seed run.
- Avoid dropping collections on application startup.

### Login fails
- Confirm the user exists and the seed script completed.
- Confirm password was hashed and compared with bcrypt.
- Check email normalization.
- Confirm JWT/session secret is configured.
- Do not log the password.

### 401 Unauthorized
- Verify login response and cookie/token handling.
- Confirm API client sends credentials/token.
- Check token expiration and frontend API base URL.

### 403 Forbidden
- Confirm the signed-in role.
- Check route middleware and resource ownership.
- Do not “fix” this by removing authorization checks.

### Data not showing in dashboard
- Inspect API response and browser Network tab.
- Check author ID mapping between users and books.
- Verify seeded books use the expected source IDs.
- Confirm the frontend handles `{ data: ... }` response envelopes correctly.

### Null date or amount breaks UI
- Use safe formatters.
- Distinguish `0` from `null`.
- Do not call date formatting functions on null/invalid dates.

### AI API returns an error
- Confirm provider key exists in server environment.
- Confirm model name is available to the account.
- Check provider rate limits, network access, and billing/access status.
- Apply request timeout.
- Do not block ticket creation.
- Show “AI unavailable — manual review required”.
- Keep manual category/priority and response controls available.

### AI returns malformed JSON
- Parse inside try/catch.
- Validate category and priority against allowed lists.
- Use a safe fallback; never trust arbitrary values.
- Do not expose raw provider output to the author.

### Admin reply does not appear for author
- Confirm response is stored as public.
- Confirm author endpoint includes public messages only.
- Confirm polling timer is active and cleanup is correct.
- Confirm the ticket owner matches the logged-in author.
- Inspect API status and Network tab.

### Deployment works locally but not online
- Confirm all production environment variables.
- Use deployed API URL in frontend build.
- Check CORS origin.
- Check database network allowlist.
- Review hosting logs.
- Rebuild/redeploy frontend after changing Vite environment variables.

## Safe debugging output
Prefer logs like:
- `AI provider request failed: timeout`
- `Ticket creation saved; AI analysis unavailable`
Avoid logs containing:
- Passwords
- JWTs or cookies
- API keys
- Full database URIs
- Unnecessary personal data
