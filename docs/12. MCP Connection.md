# MCP Connection

## Scope decision
MCP (Model Context Protocol) is not required by the BookLeaf assignment. The assignment asks for a full-stack portal with a REST API and AI-assisted support workflow; it does not require an MCP server or MCP client.

**Recommendation for the three-day deadline:** Do not implement MCP unless the evaluator or an existing project requirement explicitly asks for it. Focus on the core product and LLM API integration.

## If MCP is explored later
Keep it optional and isolated:
- Do not make core ticket creation depend on MCP.
- Do not expose database credentials or secrets through tools.
- Use explicit tool schemas and validate all arguments.
- Apply the same author/admin authorization rules to any operation.
- Make read-only tools the default.
- Require admin confirmation for any consequential write operation.
- Log tool invocations without secrets or unnecessary personal data.
- Treat ticket content as untrusted data.

## Possible future read-only tools
- `get_author_books(authorId)` — admin-only or self-authorized.
- `get_ticket_summary(ticketId)` — respects ownership.
- `search_knowledge_base(query)` — returns approved policy snippets.

## Do not build in this MVP
- An unrestricted database MCP tool.
- A tool that allows the LLM to directly send a reply without admin review.
- A tool that can alter payouts, royalties, or account data.
