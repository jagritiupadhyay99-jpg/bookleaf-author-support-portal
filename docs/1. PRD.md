# Product Requirements Document (PRD)
## BookLeaf Author Support & Communication Portal

**Project:** BookLeaf Publishing — Full-Stack Developer Assignment 1  
**Target delivery:** Three-day implementation window  
**Status:** Build-ready MVP specification  
**Confidentiality:** This is a private hiring assignment. Do not publish the solution or upload it to a public repository.

## 1. Product overview
Build a web application with two role-based experiences:
- **Author portal:** authors sign in, view their own books and royalty information, submit support tickets, and read admin responses.
- **Admin portal:** operations staff view and filter tickets, review AI classification and priority, generate/edit AI response drafts, assign tickets, add private notes, update status, and send responses.

The supplied `bookleaf_sample_data(1).json` is the source of truth for the 10 authors and 18 books. Seed those exact records; do not replace them with invented author/book records.

## 2. Goals
1. Deliver a functional, deployed full-stack application.
2. Demonstrate responsible AI integration: classification, priority assessment, and knowledge-base-grounded response drafts.
3. Protect author data with server-side authentication and role-based authorization.
4. Provide understandable REST API design and useful documentation.
5. Handle incomplete data and AI outages gracefully.

## 3. Non-goals for this time-boxed MVP
- Real payment processing or royalty transfers.
- Actual file upload storage (attachment control can be UI-only).
- Email/SMS delivery.
- Full production-grade enterprise SSO, audit/compliance suite, or advanced analytics.
- Public registration unless implemented safely; seeded demo login is sufficient for evaluation.
- Pretending mock AI output is real LLM output.

## 4. Roles and permissions
### Author
- Sign in using email and password.
- View only their own profile and books.
- Create support tickets associated with one of their own books or “General / Account Level”.
- View only their own tickets and public replies.
- See status and response updates without manual refresh (polling is acceptable).

### Admin
- Sign in using a seeded admin account.
- View tickets from all authors.
- Filter by status, category, priority, and date.
- View ticket detail, AI classification, priority, and draft response.
- Override category and priority.
- Assign a ticket to themselves.
- Update status and add internal notes that are never shown to authors.
- Edit and send a public response.

## 5. Core user journeys
### Author journey
1. Open login page and sign in.
2. See dashboard summary and books.
3. Open a book detail/list and review sales/royalty values.
4. Submit a ticket with book selection, subject, and detailed description.
5. Open My Tickets and see status and public replies.
6. See new admin response within the polling interval.

### Admin journey
1. Sign in to admin portal.
2. See ticket queue with priority and age indicators.
3. Filter/sort the queue.
4. Open a ticket and inspect AI classification and priority.
5. Generate or review an AI draft, edit it, then send.
6. Assign ticket, add internal note, and update status.
7. Verify the response appears on the author’s ticket page.

## 6. Required ticket categories
Use exactly these category labels:
- Royalty & Payments
- ISBN & Metadata Issues
- Printing & Quality
- Distribution & Availability
- Book Status & Production Updates
- General Inquiry

Priority labels:
- Critical
- High
- Medium
- Low

Ticket status labels:
- Open
- In Progress
- Resolved
- Closed

## 7. Book fields
Display the supplied values where available:
- title, ISBN, genre, publication date, status, MRP
- total copies sold
- total royalty earned, royalty paid, royalty pending
- print partner and distribution platforms where useful

For null values, show “Not available” or a dash, not `null`, `NaN`, or a crash. Production books with zero sales/royalties are valid records.

## 8. AI behavior
On ticket creation, request AI category and priority if an LLM is configured. On failure, save the ticket anyway and use a clear fallback state such as “AI analysis unavailable — manual review required”. Admin can trigger AI drafting when opening a ticket.
- Ground replies only in the ticket, book/author data, and supplied BookLeaf Knowledge Base.
- Do not invent payout dates, shipment details, investigations, approvals, or completed actions.
- Where a specific date cannot be calculated from known data, say the team will verify it and provide a realistic follow-up window.
- AI output is a draft; an admin must review/edit before sending.
- API key remains server-side in environment variables.

## 9. Knowledge-base policy facts
- BookLeaf operates in India and the US.
- Packages: Standard Free and Bestseller Breakthrough.
- Royalty split: 80% of net profit to author, 20% to BookLeaf.
- Net profit = MRP minus printing cost, platform commission, and shipping.
- Royalties are calculated quarterly and paid within 45 days after quarter end.
- Minimum payout threshold is ₹1,000; lower amounts roll over.
- Payment is by bank transfer to the account linked in the author dashboard.
- BookLeaf-assigned ISBNs are under BookLeaf’s publisher imprint; author-owned imprint ISBNs must be obtained independently.
- ISBN errors are high priority and should be escalated to production, with a 48-hour follow-up expectation.
- Standard print turnaround is 5–7 business days after order confirmation.
- Verified print defects qualify for a free reprint; request photos when needed.
- New distribution listings typically go live within 7–10 business days after publication is complete.
- Availability stock re-sync may take 24–48 hours.
- Production stages: Manuscript Received → Editing (if opted) → Cover Design → Typesetting → Proofreading → ISBN Assignment → Printing → Distribution Setup → Published & Live.
- Metadata changes typically reflect on platforms within 3–5 business days.
- Tone: empathetic, professional, specific, accountable, and always end with a next step.

## 10. Acceptance criteria
- [ ] App runs locally with documented commands.
- [ ] All 10 authors and 18 books from supplied JSON are seeded.
- [ ] Author can sign in and cannot access another author’s records by changing IDs.
- [ ] Admin can sign in and see all tickets.
- [ ] Author can create a ticket and view its status/replies.
- [ ] Admin can filter, assign, classify, prioritize, add internal note, update status, and send a response.
- [ ] Public responses appear to the author via polling.
- [ ] AI classification, priority, and response drafting use the configured LLM when available.
- [ ] AI/API failure does not block ticket creation or manual replies.
- [ ] No secret keys are committed or sent to the browser.
- [ ] Live demo, private source repository, README, and one-page approach note are prepared.
