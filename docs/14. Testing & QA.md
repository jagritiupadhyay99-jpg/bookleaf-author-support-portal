# Testing & Quality Assurance Plan

## 1. Automated checks
Run:
- Client production build.
- Server lint/test scripts if configured.
- Unit tests for validation, priority/category parsing, and null-safe formatting.
- API tests for auth, ownership, admin-only routes, and ticket workflow.

Do not claim a test passed unless it was actually executed.

## 2. Seed data checks
- [ ] Exactly 10 authors are loaded.
- [ ] Exactly 18 books are loaded.
- [ ] Source IDs remain unique.
- [ ] Running seed twice does not duplicate records.
- [ ] Null publication dates and MRP are retained.
- [ ] Zero royalty values remain zero.

## 3. Authentication/security cases
- [ ] Valid author login succeeds.
- [ ] Invalid password fails with a safe message.
- [ ] Missing token/cookie returns 401.
- [ ] Author cannot call admin endpoints.
- [ ] Author cannot view another author's books.
- [ ] Author cannot view another author's ticket by changing ID.
- [ ] Author cannot attach a ticket to another author's book.
- [ ] Admin can view and manage tickets.
- [ ] Internal notes are not included in author responses.
- [ ] Password hashes are never returned.

## 4. Ticket workflow
- [ ] Missing subject rejected.
- [ ] Missing description rejected.
- [ ] General/account-level ticket can be created without a book.
- [ ] Book-specific ticket validates book ownership.
- [ ] New ticket starts Open.
- [ ] Ticket appears in author My Tickets.
- [ ] Admin sees the ticket.
- [ ] Category and priority can be overridden.
- [ ] Assignment to current admin works.
- [ ] Status can be changed.
- [ ] Internal note saves and remains private.
- [ ] Public response saves and appears to author.
- [ ] Polling displays new response without manual refresh.

## 5. AI cases
- [ ] Royalty question is classified appropriately.
- [ ] ISBN mismatch is treated as high priority.
- [ ] Printing defect uses the relevant quality policy.
- [ ] Distribution unavailability uses stock-sync policy.
- [ ] Production delay uses current book status if available.
- [ ] Invalid model JSON falls back safely.
- [ ] Missing key/provider timeout does not block ticket creation.
- [ ] Admin can manually edit category, priority, and reply.
- [ ] Draft is not sent automatically.
- [ ] AI output does not invent an exact payout date or completed action.

## 6. UI/UX cases
- [ ] Loading state appears while data loads.
- [ ] Empty ticket list is understandable.
- [ ] API errors are shown without stack traces.
- [ ] Null fields show “Not available”.
- [ ] Mobile/tablet layout remains usable.
- [ ] Forms show clear validation.
- [ ] Status and priority include text labels, not color alone.

## 7. Deployment smoke test
- [ ] Frontend live URL opens.
- [ ] Backend health endpoint responds.
- [ ] Login works on deployed environment.
- [ ] Database connection is healthy.
- [ ] Demo dataset exists in deployed database.
- [ ] Author can create ticket.
- [ ] Admin can respond.
- [ ] Author sees reply after polling interval.
- [ ] Environment variables are configured correctly.
- [ ] Repository remains private.
